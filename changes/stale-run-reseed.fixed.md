A run's progress bar (an import's fetch, a refresh, the auto-read catch-up) no longer stays on screen after the run has finished, and no longer reports a run as finished while it is still going, when a reply from the server was built a moment before the change and arrives after it. When Kipple loses track of how a run ended, the import and the auto-read catch-up now say it ended without claiming a result. The server's status, bootstrap, refresh, import and catch-up answers carry `event_id` for this. (#536)
